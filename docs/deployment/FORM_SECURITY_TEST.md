# 公共表单安全测试

## 一、确认服务状态

1. 打开 `http://localhost:3000/health`。
2. 确认 `database.status` 和 `redis.status` 都是 `up`。
3. Redis 不可用时系统仍能提交，但正式上线前必须让 Redis 恢复正常，保证多台服务器共享限流和防重复状态。

## 二、小程序正常提交

1. 在微信开发者工具中进入任意申请表。
2. 填写完整信息并点击提交。
3. 提交期间按钮应显示“正在提交”且无法再次点击。
4. 后台“客户线索”中应只新增一条记录。

## 三、重复提交保护

1. 在网络较慢时快速连续点击提交按钮。
2. 页面不应发出多次有效提交，后台只应出现一条线索。
3. 同一次请求因网络断开而重试时，API 返回第一次创建的线索，不再创建新记录。

## 四、字段安全

1. 后台创建或编辑表单时，单个表单最多配置 50 个字段。
2. 单个选择字段最多配置 50 个选项，重复选项会被拒绝。
3. 危险的嵌套正则规则会被拒绝，页面显示“格式校验规则不安全”。
4. 小程序提交后台未配置的字段、超长内容或异常手机号时，API 应拒绝请求且不创建线索。

## 五、防刷验证

默认策略是同一 IP 在 10 分钟内最多提交 20 次，同一 IP 对同一表单最多尝试 6 次。超过后接口返回 `429` 和“提交过于频繁，请稍后再试”。

正式上线时在服务器 `api-server/.env` 中维护以下参数：

```env
TRUST_PROXY_HOPS=1
PUBLIC_FORM_RATE_WINDOW_SECONDS=600
PUBLIC_FORM_RATE_IP_MAX=20
PUBLIC_FORM_RATE_FORM_IP_MAX=6
PUBLIC_FORM_MAX_BODY_BYTES=32768
PUBLIC_FORM_ALLOWED_SOURCES=wechat_miniprogram,web
```

修改环境变量后必须重启 API 才会生效。Nginx 直接位于 API 前方时 `TRUST_PROXY_HOPS=1`；没有反向代理时改为 `0`，不能随意调大。

## 六、上线前检查

- Redis 健康状态为 `up`；
- Nginx 只转发可信的客户端 IP 请求头；
- `PUBLIC_FORM_ALLOWED_SOURCES` 只保留实际启用的小程序和网页来源；
- API 日志中看不到姓名、手机号和动态字段原文；
- 使用 HTTPS 域名，且该域名已加入微信小程序服务器域名白名单。
